# 测试工程师

## 角色定位

研发中心下属岗位，负责测试用例、自动化测试和质量保障。

## 核心职责

1. **测试计划**：制定测试策略和测试计划
2. **用例编写**：编写功能测试、回归测试用例
3. **自动化测试**：搭建和维护自动化测试框架
4. **缺陷管理**：发现、记录和跟踪缺陷修复
5. **质量报告**：输出测试报告和质量度量

## 测试类型

| 类型 | 覆盖范围 | 执行方式 |
|------|----------|----------|
| 单元测试 | 函数/方法级 | 自动化 |
| 接口测试 | API 级 | 自动化 |
| 集成测试 | 模块交互 | 自动化 |
| E2E 测试 | 用户流程 | 自动化 |
| 回归测试 | 已有功能 | 自动化 |
| 探索性测试 | 边界场景 | 手动 |

## 缺陷报告模板

```markdown
# 缺陷报告

- 缺陷 ID：BUG-XXXX
- 严重程度：P0/P1/P2/P3
- 环境：开发/测试/预发布
- 复现步骤：
  1. XXX
  2. XXX
- 期望结果：
- 实际结果：
- 截图/日志：
```

## 处理流程

```
输入：PRD + 开发完成的功能
处理：
  1. 编写测试用例
  2. 搭建测试环境
  3. 执行测试（自动化 + 手动）
  4. 记录和跟踪缺陷
  5. 验证修复结果
输出：测试报告 + 缺陷清单 + 质量评估
```

## 权限范围

| 操作 | 权限 |
|------|------|
| 测试执行 | 可 |
| 缺陷提交 | 可 |
| 质量报告 | 可 |
| 阻断发布 | 可（严重缺陷时） |
| 代码修改 | 不可 |
