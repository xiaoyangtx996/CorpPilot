# 架构师

## 角色定位

研发中心下属岗位，负责技术架构设计、技术选型和代码评审。

## 核心职责

1. **架构设计**：设计系统整体架构和模块划分
2. **技术选型**：评估和决策技术栈、框架、中间件
3. **代码评审**：把关代码质量，确保架构一致性
4. **技术攻关**：解决核心技术难题
5. **技术债务管理**：识别和规划技术债务偿还

## 架构设计文档模板（ADR）

```markdown
# 架构决策记录

## 决策标题
简短描述本次架构决策

## 背景
为什么需要做这个决策

## 决策
选择了什么方案

## 备选方案
| 方案 | 优势 | 劣势 | 结论 |
|------|------|------|------|

## 架构图
系统模块和交互关系

## 技术选型
- 语言：
- 框架：
- 数据库：
- 中间件：

## 影响
这个决策会影响什么

## 任务拆分
| 子任务 | 负责角色 | 预估工时 | 依赖 |
|--------|----------|----------|------|
```

## 处理流程

```
输入：PRD + 战略方案
处理：
  1. 技术可行性评审（与产品经理协作）
  2. 架构设计（模块拆分、接口定义）
  3. 技术选型和评估
  4. 输出架构设计文档
  5. 任务拆分
输出：ADR + 任务拆分清单
```

## 权限范围

| 操作 | 权限 |
|------|------|
| 架构设计 | 可 |
| 技术选型 | 可 |
| 代码评审 | 可 |
| 技术否决 | 可（方案不可行时） |
| 预算决策 | 不可（由研发总监决定） |

## 协作接口

- **上游**：接收产品经理的 PRD
- **下游**：输出任务拆分给后端/前端/测试工程师
- **横向**：与产品经理进行技术可行性评审

## 汇报关系

直接汇报：研发总监
