# CorpPilot · 企业智脑

> 基于国内大厂组织架构的多智能体协作系统

[![License](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
[![Python](https://img.shields.io/badge/python-3.10+-green.svg)](https://www.python.org/)

## 核心特性

**四层架构 · 分权制衡 · 岗位细分**

| 层级 | 职责 | 部门负责人 | 子角色（岗位） |
|------|------|------------|----------------|
| **决策层** | 战略决策 | CEO、总裁办主任、战略总监 | 行政秘书、信息专员、战略分析师、商业分析师 |
| **审核层** | 风险把控 | 风控总监、PMO 主管 | 风险分析师、合规专员、安全工程师、项目经理、Scrum Master |
| **执行层** | 任务执行 | 研发总监、产品总监、数据总监、运营总监、市场总监 | 架构师、后端/前端工程师、测试/运维工程师、产品经理、UI/UX 设计师 等 |
| **支撑层** | 资源保障 | 财务总监、法务总监、HR 总监 | 会计、财务分析师、合规律师、HRBP、招聘专员、培训专员 等 |

**部门负责人 + 默认岗位 Agent + HR 动态扩缩容**

- 每个部门有一个负责人管理团队
- 每个岗位默认 1 个 Agent（最小编制）
- 大项目时 HR 动态创建多个同类型 Agent 并行协作
- 项目结束后 HR 回收动态 Agent

**董事会决策机制**

- 正常流程：讨论 → 投票 → 多数同意执行
- 紧急流程：董事长直接下令

## 任务流转

```
董事会决策 → 总裁办分拣 → 战略部规划 → 风控审核 → PMO 派发 → 部门执行 → 完成
     ↑                                                              ↓
     └────────────────── 驳回修改 ←──────────────────────────────────┘
```

### 部门内部执行流程（以研发中心为例）

```
PMO 派发任务
    │
    ▼
研发总监：评估复杂度，人力不足时向 HR 申请动态 Agent
    │
    ▼
架构师：技术方案设计 + 与产品经理评审
    │
    ▼
后端/前端工程师：编码实现
    │
    ▼
架构师：代码评审
    │
    ▼
测试工程师：测试验证
    │
    ▼
运维工程师：部署上线
    │
    ▼
研发总监：确认交付 → 通知 HR 回收动态 Agent
```

### HR 动态扩缩容

```
部门人力不足 → PMO 评估 → HR 创建动态 Agent → 项目执行 → 项目完成 → HR 回收
```

**决策模式**：
- **正常流程**：董事会讨论 → 投票表决 → 多数同意执行
- **紧急流程**：董事长直接下令，无需投票

### 动态扩缩容示例

```
默认编制（最小配置）：
  研发中心 = 研发总监 + 架构师(1) + 后端(1) + 前端(1) + 测试(1) + 运维(1)

大项目扩容后：
  研发中心 = 研发总监 + 架构师(1) + 后端(5) + 前端(3) + 测试(2) + 运维(1)
                                     ↑           ↑           ↑
                              动态创建 +4    动态创建 +2   动态创建 +1
                              项目结束后由 HR 回收
```

## 使用方法

### 向 AI 下达任务

```
用户：请帮我开发一个用户增长系统

总裁办（信息专员）：收到任务，分拣为【技术研发 RD】，优先级 P1
战略发展部（商业分析师）：已完成方案设计，资源评估 15 人天
风控中心（风险分析师）：审核通过，风险可控
PMO（项目经理）：已派发至研发中心，分配 5 后端 + 3 前端
    →（人手不足）向 HR 申请额外 4 个后端 + 2 个前端 Agent
HR（招聘专员）：已创建 backend_dev_001~004、frontend_dev_001~002
研发中心：
    架构师：技术方案设计完成
    后端工程师(x5)：编码实现中...
    前端工程师(x3)：编码实现中...
    测试工程师：测试验证通过
    运维工程师：部署上线完成
研发总监：项目交付完成
HR（招聘专员）：已回收动态 Agent
```

### 自定义 Agent

编辑 `agents/{role}/SOUL.md` 定义部门负责人，编辑 `agents/{role}/roles/*.md` 定义子角色。

## 技术亮点

- **零依赖后端**：Python 标准库实现 API 服务器
- **单文件看板**：纯 HTML/CSS/JS，无需构建
- **状态机保护**：任务流转受 `_VALID_TRANSITIONS` 约束
- **文件锁机制**：防止多 Agent 并发写入冲突
- **完整审计日志**：所有操作可追溯
- **部门名册管理**：`department_roster.json` 统一管理静态和动态 Agent
- **SOP 规程**：关键流程有标准操作规程
