# 浏览器工作台开发

本阶段已实现持久身份管理、私聊与董事会/项目群、成员管理、归档/恢复、历史分页与 Owner 消息发送。
已接入指定成员的模型回复请求与Run状态、任务需求卡与历史、执行成果评审、个人／项目批准记忆、未知执行核查及 Owner 明确确认的协作项目组建；真实Worker集成、模型提案与自动协作仍在开发，不能视为完整目标验收。

后续桌面打包沿用此静态构建和服务协议，具体宿主通信、关闭、凭据及升级门禁见 [Tauri 2 迁移方案](../docs/tauri-migration.md)。当前没有 Tauri 构建或安装命令。

需要 Node.js 22.12+（开发机可用 Codex bundled Node 24.19）、Python 3.11+。

在 `frontend` 目录运行：

```powershell
npm ci
npm run build
```

从仓库根启动 Python 服务（先创建 `.venv`）：

```powershell
Set-Location scripts
..\.venv\Scripts\python.exe -m workbench.server --port 7892
```

打开 `http://127.0.0.1:7892`。服务只监听本机，直接提供 `frontend/dist`、身份与会话 API。
默认数据在用户 `LOCALAPPDATA/CorpPilot/workbench` 下，源码重建不删除身份。可用 `--data-dir` 指定测试目录；数据库不得放入静态构建目录。
Ctrl+C 停止服务；重启使用同一数据目录。

点击 Agent 开启固定私聊，或新建群聊并选择成员。历史每次正向加载 50 条；“刷新消息”读取新增消息，当前不自动轮询。
发送失败保留当前页面内的草稿和请求 ID，相同内容重试不会重复落库；未发送草稿不保证刷新页面后恢复。
从 v1 数据库启动时会自动升级到 v2，并在数据目录留下独立 `workbench-before-migration-*.sqlite3` 快照，避免并发启动覆盖备份。

左栏“模型设置”可保存模型名、OpenAI兼容API基础地址、密钥环境变量名及执行参数。配置默认禁用；保存不调用模型，也不代表连接测试通过。
当前密钥须在启动服务前设置到进程环境，设置界面只显示该变量是否存在，不显示或存储其值。软件内密钥录入与真实供应商验收仍待实现。

左栏“CLI 设置”管理 Codex CLI 的绝对 `.exe` 路径、模型、密钥环境变量名、1–3600 秒超时及 1–16 并发数。初始禁用、超时 120 秒、并发 2；启用须显式勾选，保存仅提交修改字段，不运行程序或模型。读取失败时禁止编辑，可重试读取。
当前 CLI 为 Windows 本机可信工具，工作目录隔离不是 Docker 沙箱；Codex 适配器使用 OpenAI API，不复用聊天的 API 基础地址。密钥只从服务进程环境读取。路径存在和环境变量存在均不代表可执行或账号有效。
“检查已保存 CLI 版本”只运行已保存程序的 `--version`，不调用模型，不验证账号，不调度任务。存在未保存修改时须先保存，再手动检查；版本检查请求最多等待 30 秒，界面显示成功、失败或请求错误。

模型配置完整并启用后，保存Owner消息，再点击“请 Agent 回复”、选择成员并确认才发起调用。该动作可能产生已配置服务商的费用；普通发送消息不会自动唤醒成员。
Run 持久显示排队、运行、完成、失败、取消或未知。排队可取消；运行中尚不能主动停止，本地请求有总超时，远端是否已执行无法保证。失败/未知不自动重发；同一源消息/成员查询沿用原请求。
一个数据目录只允许一个控制服务，活动回复最多100个，执行并发和RPM按模型设置控制；RPM窗口在重启后归零。此回复请求进程不等同于隔离CLI/Docker Worker。

Owner 消息下“创建任务”打开需求表单：标题、范围、验收标准和启用的会话成员负责人均必填。保存只持久化需求，不调用模型、不启动执行，也不产生执行状态。会话任务卡显示需求版本、负责人、来源消息 ID；来源不在已加载历史中时可继续加载消息历史。
编辑提交全部需求字段及基准版本；409 冲突保留草稿，必须点击“读取最新版本并保留草稿重新编辑”后对照最新内容再保存。历史版本对话框独立读取只读快照。停用或移出的负责人仍显示，编辑时必须改选启用成员；归档会话任务只读。
创建前将原始请求与 ID 存入当前标签页 sessionStorage。未知结果锁定字段，仅能沿用原内容“重试原请求”；切换会话或刷新同一标签页后可从“核对待确认任务”恢复。存储失败则不发送创建请求；普通未提交草稿只保留在当前页面内。关闭标签页或主动清理浏览器会话存储会丢失待确认记录，遇到此情况应先读取任务列表核对，不要直接重复创建。

Owner 消息下“组建协作项目”可一次建立项目群、成员、1–16 项任务及任务依赖。共享摘要初始为空，须主动填写可向成员共享的内容；原消息仅供对照，不自动复制源会话历史。协调人必须是源会话内已启用成员，任务负责人可从已启用身份中选择；技能标签只供参考。填写目标、范围和验收标准，检查依赖无环，并确认完整计划和成员后才可提交。创建不会调用模型或启动 CLI，成功后可“打开已创建的项目群”。

左侧“协作计划与恢复”展示当前源会话最近100条已批准原计划，也可恢复当前标签页唯一的待确认协作请求。发送前保存原来源和完整计划；切换会话或刷新后恢复的是原来源，不会换成当前会话。首次明确拒绝可点“修改首次未接受的计划”，保留全文修改并重新确认；选择“核对原协作请求”后，若结果未知则仅沿原键核对，不能继续沿用此前拒绝证据创建替代项目。核对可能首次创建服务端尚未收到的已确认计划，但不会调用模型或 CLI。

回执必须与原来源、请求键和完整计划一致才算确认；读取失败不表示没有项目，已确认回执会保留供打开。源会话后来归档仍可核对已提交请求及历史，不能创建新计划。普通未提交草稿不保证刷新恢复；会话存储损坏时禁止新建，关闭标签页或清理存储后须先读历史核对，避免重复创建。此浏览器入口的验证证据见 [验收报告](../docs/acceptance-report.md)；模型生成提案与按技能自动路由仍未实现。

开发时另开终端在 `frontend` 运行 `npm run dev`；Vite 将 `/api` 转发到本机 7892。只转换同源开发请求的 Origin，跨来源请求仍由 API 拒绝。

```powershell
npm run typecheck
npm run build
```

后端及 HTTP 回归从仓库根运行 `.venv\Scripts\python.exe -m pytest tests/ -q`。测试依赖 pytest、Pillow；测试数据写临时目录。
前端是静态 SPA，不依赖 Tauri/Node 宿主 API。生产运行不需要 Vite 服务，Tauri 接入后仍可复用静态构建与业务协议。

### 目标执行与浏览器回归

Owner 消息下“交给秘书组织并执行”可明确选择共享摘要、协调人、候选身份和任务上限，一次授权秘书规划并启动固定首批任务。可选择按依赖自动交接中间成果，最终成果仍由 Owner 验收。左侧“目标执行与恢复”核对原请求、查看目标历史及请求停止。次数上限不是货币预算；未知状态不会自动重新规划。关闭标签页会失去本地 sessionStorage 待确认记录，服务端目标历史仍保留。

安装仓库 Python 测试环境后，在 frontend 目录运行：

```powershell
npm ci
npm run test:browser:install
npm run test:browser
```

该命令先做类型检查和生产构建，再使用 Chromium 验证真实 Vite 开发模式及生产页面。每次生成独立临时数据目录、回环 HTTP 模型 fixture 和受控 CLI runner，覆盖授权恢复、固定批次、成果下载与最终验收及停止；不调用付费模型或真实 CLI/Docker，不写正常应用数据。结束时关闭测试服务，保留报告和截图。默认 Python 为仓库 .venv，可用 CORPPILOT_PYTHON 指定；CORPPILOT_BROWSER_OUTPUT 可指定证据父目录，浏览器覆盖路径为 PLAYWRIGHT_CHROMIUM_EXECUTABLE。报告路径由命令输出；故障注入产生的预期 400/503/断线单列保存。401 边界使用模拟读取失败，不代表真实服务重启或令牌轮换验收。

任务卡“执行记录与控制”读取实际 CLI 执行历史和配置状态。首次执行须勾选明确确认；再次执行须核查最近一次执行并填写结果、副作用及重试理由。负责人必须有 execute 权限，CLI 必须配置完整并启用。排队可取消，运行中可请求停止；“正在停止”会继续轮询，只有实例退出后才显示取消。成功退出仅进入待评审，不表示成果获批。
执行提交前把精确请求写入当前标签页 sessionStorage；结果未知时保留同一请求 ID、需求版本和前次执行引用。刷新同一标签页并重新打开任务后可核对原请求；列表找到匹配记录时自动确认，不会重复执行。原请求尚未被服务端接收时，手动核对可能首次启动该请求。存储无效或不可读取时禁止新建；不要清除会话存储来绕过待确认状态。未知执行禁止替代实例，需求冲突不会自动切换到新版重试。关闭窗口停止轮询，不停止服务端执行。
首次提交收到明确 4xx 拒绝时，界面持久记录拒绝状态，并提供“撤销未接受请求”以修正配置或刷新需求后重新确认。经历断线、超时或其他未知结果的请求即使重放收到 4xx，也不会出现撤销入口，仍只沿用原请求核对。

任务执行记录中展开“成果与 Owner 评审”，可下载已保存文件并查看大小、SHA-256 和 Owner 决定。下载使用附件响应，不在工作台内执行 HTML。批准前须查验完整成果、填写理由并勾选确认；空成果不能批准，可填写理由拒绝。评审读取最新需求、执行及成员权限，不要求启用 CLI，也不启动模型。
每次执行只有一个不可覆盖的批准或拒绝，绑定原需求版本及成果快照。后续修改需求或再次执行，历史批准不会自动作为当前任务通过。若读取当前状态失败，界面明确标注尚未核对。
评审提交前保存精确请求到当前标签页 sessionStorage；断线后刷新并重新展开可“核对原评审请求”，即使读取接口失败仍可沿原键核对。首次明确拒绝可撤销未接受评审；曾经结果未知的请求只保留原键，不自动生成替代决定。关闭标签页会失去该浏览器待确认记录，应先查看服务端决定。

已配置任务依赖的执行，在前置当前版本和最新执行获得Owner批准后，CLI会读取独立的 inputs/{成果ID} 副本。提示词提供原文件路径、来源执行、大小与hash映射；只传直接前置的批准成果，不挂载其他Agent目录。输入限额为100文件、每文件4MiB、合计16MiB；校验或准备失败不启动CLI。任务卡“前置任务”可配置依赖，依赖API见架构文档；真实模型与双Docker隔离尚未验收。

任务卡“前置任务”可选择同会话内最多32个前置，不能选择自身或构成循环；变更生成新需求版本，历史版本保留当时的任务ID清单。面板和执行窗口显示前置验收条件，满足前置不代表本任务完成。会话归档、负责人停用或移出后只能查看。
依赖保存前将原版本和选择存入标签页sessionStorage，断线后重新打开可重试原版本。409保留草稿；读取最新状态不会覆盖选择，必须点击“已对照最新状态，保留草稿重新编辑”才采用新版本。当前选择相同仅表明状态一致，不证明之前的请求已确认。未提交选择关闭后丢弃，已发送待确认请求会保留。

未知执行的 Owner 核查 API：GET /api/workbench/execution-reconciliations/pending 定位未核查项，GET/POST /api/workbench/executions/{id}/reconciliation 查看或保存核查。该记录保留原unknown与未观测退出码；全部未知项核查后，既有已授权队列可能继续运行。同任务重试仍要独立创建新尝试。浏览器入口已接入，操作见下文；不要通过修改数据库、虚假声明停止或清除历史来解除阻塞。

左侧“执行核查”列出尚未核查的未知 CLI 执行，显示任务名和负责人；归档会话、停用身份的历史记录也可核查。任务执行记录中的“查看与核查未知执行”可回看已保存声明。
核查必须实际确认原进程及子进程已停止、检查外部影响，并填写依据。保存的是不可覆盖的 Owner 声明，不会停止进程、改写 unknown/退出码或批准成果；最后一个未知项核查后，可能恢复所有此前已授权的排队 CLI 任务。新尝试仍需在任务内单独确认。
核查请求在发送前保存在当前标签页 sessionStorage，断线刷新后从全局入口按原 ID、attempt、需求版本及全文重试。读取失败不视为无记录；若另一窗口已保存不同声明，成功读回并明确确认后可结束本地等待，不会声称本地请求已获接受。

CLI设置的“启用本机资源准入”可按实际可用内存和逻辑CPU限制新的执行启动。为宿主保留内存，本地执行使用设置的每实例预约，Docker使用每容器资源配置。资源不足保持排队，恢复后继续原请求；修改配置可能恢复此前已授权任务。活动预约保留到退出结果成功落库，不因修改配置提前缩减。状态可手动刷新；探测失败显示未知，启用时暂停新任务。本地预约是保守启动门，不是进程硬限，也不是费用预算。默认关闭以保留旧配置行为。

右侧“Agent视角”的“任务与实际活动”按身份显示当前负责的任务、实际执行和模型活动，各类最近50条及总数。可刷新或打开原任务全部执行、所属会话。任务改派不改变旧执行归属，历史批准不自动代表新需求通过。此入口只供Owner观察，不将所见资料发送给Agent；token用量不代表已核算费用，完整工具调用和模型上下文尚未展示。
