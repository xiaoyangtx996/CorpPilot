# CorpPilot 工作台设计规格

状态：设计交接稿，运行界面与接口尚待实现和验收。依据完整 Goalcraft 目标，不将主屏完成等同于产品完成。

概念来源：[主屏概念](assets/workbench-concept.png)，原生尺寸 1536 × 1024，使用内置 Imagegen 生成并由前端代理查看。该图是视觉参考，示例消息、素材管理任务、时间、在线状态均不是业务初始化数据。

## 1. 视觉方向和页面结构

使用清晰的中文三栏工作台：左侧选择会话与长期身份，中间交流与执行任务，右侧查看所选身份的活动和记忆。纯白主内容、冷灰导航、深绿操作色、细分隔线。保持开放列表与聊天时间线，仅任务和产物使用有边界的内容块。不新增营销标题、指标卡片阵列或组织审批地图。

1536 px 桌面参考：左栏 320 px，中栏弹性占剩余空间，右栏 388 px；顶部 68 px。外框各区共享分割线，无大型圆角套壳。左栏会话列表与身份列表分别有标题；设置固定底部。中栏标题、可滚动消息流、底部输入区。右栏身份选择器、活动/记忆页签、按需展示的信息分区。中栏最小宽度 400 px，不允许消息或代码块将整个页面撑宽。

断点：大于等于 1280 px 三栏；900–1279 px 左栏 260 px，右栏通过“Agent 视角”按钮打开同样内容的抽屉；小于 900 px 单栏会话，顶部提供会话导航与身份详情入口，抽屉关闭后恢复触发元素焦点。窄屏不同时挤压三栏。表单宽度 `min(560px, viewport - 32px)`，长表单主体滚动、操作区可见。

## 2. 设计 tokens

以下为从概念提炼的近似值；实现时与同尺寸浏览器截图比对修正，避免凭个人喜好改变颜色温度。

| Token | 值 | 用途 |
| --- | --- | --- |
| background | #FFFFFF | 中栏、详情、表单 |
| sidebar | #F6F7F9 | 左导航 |
| surface-muted | #F5F6F8 | Agent 消息、低强调区域 |
| selected | #E5EFEC | 选中会话、Owner 消息 |
| text | #17201D | 正文标题 |
| text-muted | #626B77 | 次要说明、时间 |
| border | #DDE2E7 | 1 px 分隔线和输入边框 |
| accent | #08765D | 主按钮、选中页签、品牌字 |
| accent-hover | #06634F | 主按钮悬停 |
| warning / error | #9A5900 / #B42318 | 待处理、失败文本，配浅色背景 |
| focus | #0A8067 | 2 px 焦点环，2 px 间隔 |
| radius | 6 / 8 px | 按钮/输入、消息/任务卡 |
| spacing | 4, 8, 12, 16, 20, 24, 32 px | 同类元素使用同档间距 |

字体：`Inter, "Segoe UI", "Microsoft YaHei", sans-serif`，中文使用系统字体，无必需联网字体。品牌 26/32、页面标题 24/32、分区标题 16/24、正文和消息 16/26、控件及列表 14/22、时间和辅助信息 12/18；标题 600，其余 400–500。按钮、输入、页签显式设置字族、字号、行高，禁止依赖浏览器默认。任务卡宽度上限 560 px，消息宽度上限 85%；长路径及长词换行，代码块内部横向滚动。

常规过渡 120 ms，仅颜色和抽屉位移；遵循 reduced-motion。无闪烁状态灯或无依据的“正在输入”动画。普通面板无阴影，对话框使用低强度阴影。

## 3. 图标和资产

图标为统一 20 px、1.75 px 线宽、圆端点的 SVG，含会话、群组、文件夹、加号、设置、任务剪贴板、时钟、附件、成员提及、展开/返回、关闭。复用已安装图标库；若没有，仅定义实际用到的少量 SVG，不为了几个图标增加大型依赖。箭头不使用文本字形代替。装饰图标对辅助技术隐藏，独立图标按钮必须有中文可访问名称。

有意偏差：概念中的人物头像改为稳定身份的角色首字圆形标识，用受控少量背景色区别身份。它表示身份，不暗示真实人物；不生成一组默认人物图片。品牌保留文字 CorpPilot。概念输入框的表情按钮不列入首版必需能力；附件只有上传并可访问后才能显示已附加，不能使用空按钮。所有产品文字、表单、任务卡均为原生 UI，不把概念图嵌入应用当界面。

## 4. 组件和可见文案

小型组件边界：AppShell、ConversationList、AgentList、ChatPane、TaskCard、AgentInspector、WorkbenchDialogs；共享 Button、Field、StatusLabel、EmptyState 即可，不建立配置驱动页面引擎。服务请求集中在一处，组件只使用明确的资源类型。除输入草稿、选择项和抽屉状态外，业务状态以服务回读为准。

允许的固定主屏文案：CorpPilot、会话、Agent、新建、设置、Agent 视角、私聊、活动、记忆、当前状态、当前任务、事件时间线、成果、暂无成果、发送、确认并执行、修改需求。会话标题、身份名字、消息、任务目标、验收、时间、费用及状态来自实际资源。概念中的“素材管理页面”“实现素材列表与 CSV 导入”等示例禁止作为真实聊天历史种子。

新增而必需的功能文案：新建会话、创建 Agent、创建群组、邀请成员、归档会话、恢复会话、停用 Agent、重新启用、请求停止、确认停止、从检查点恢复、编辑配置、检查连接、加载失败、重新连接。新增文案须对应实际入口，不能出现不可操作的伪功能。

身份状态由后端可验证事实形成：可用、已停用、执行中、等待、未知；“可用”仅表示身份允许接受任务。长期身份存在不等于容器在线。运行状态独立显示：排队、运行、等待输入、等待审批、停止中、已取消、失败、完成、未知。未获取状态时显示未知，禁止默认绿色在线。费用缺失显示“未提供费用”，不能显示 0 元；只有完整计量确实为零时显示零。

## 5. 主流程与任务动作

1. 第一次启动读取真实目录。没有聊天时显示“选择一位 Agent 开始会话”，可直接打开秘书私聊；默认身份由后端幂等创建，前端不硬编码岗位数量。
2. 点击身份打开或获取与该身份的私聊。发送有独立消息 ID 和发送状态；提交失败保留草稿，重试复用幂等键。聊天记录呈现待发送/失败，不提前生成 Agent 回复。
3. 讨论形成任务草案后显示任务卡：目标、范围、验收、责任人、需求版本。只有后端存在任务资源才显示任务卡。用户可修改需求或确认执行；按钮行为回读任务与 Run 状态。
4. 执行过程显示实际活动事件、成员邀请、工具摘要和产物；群组旁听不等于所有成员运行。任务卡可查看依赖子任务、评审结论和失败原因。
5. 修改运行中需求必须产生新需求版本；弹窗说明旧结果不自动适用于新版本。停止先进入停止中，后端确认实例终止后显示已取消；不能以按钮点击成功推断已停止。
6. 检查点恢复仅在后端返回可恢复检查点时可用。外部副作用未确认的运行要求先核对结果，不能默认无损重试。
7. 产物通过服务返回的受控下载/预览链接打开，禁止把任意宿主路径转为可读取 URL。未完成产物不能标记“已交付”。

## 6. 必需对话框和详情

| 表面 | 字段与操作 | 校验、回读和权限 |
| --- | --- | --- |
| 新建/编辑身份 | 名称、角色模板、职责说明、模型配置、技能、工具授权范围；保存、取消 | 名称非空、长度有限；选择有效模板/模型；范围由可授予选项选择，不能凭文本扩大宿主访问；保存回读稳定 ID |
| 停用身份 | 身份名称、活动 Run 数、停用/取消 | 有活动 Run 时明确停用仅阻止新任务或需另行停止；不得删除历史、卷和记忆 |
| 新建会话 | 私聊/群组类型、群名称、项目、成员 | 私聊选择一位启用身份；群至少一位可邀请成员；董事会/项目群使用明确类型 |
| 成员管理 | 当前成员、角色/权限、邀请、移除或退出 | 后端校验 Owner 权限；移除不删除历史，后续可见范围由服务控制 |
| 任务详情/修改 | 目标、范围、验收、责任人、预算/并发限制、版本 | 不可空目标和验收；服务校验版本冲突，不能覆盖较新修改；依赖与审批显示真数据 |
| 停止/恢复 | 实际 Run、当前状态、检查点、风险说明 | 停止确认与终止事实分开；恢复必须指定检查点及需求版本 |
| 设置 | 模型与 CLI 配置、Docker 检查、最大并发、费用边界 | 秘密字段只写入且响应脱敏；显示配置来源/是否存在，不能回填真实密钥；检查返回时间及真实错误 |
| 记忆详情 | 私有/项目范围、来源、正文、版本、候选/批准状态 | Owner 查看与 Agent 可见范围分别标明；批准/拒绝/回滚经过服务授权；无数据时不伪造经验 |

对话框使用原生 dialog 或已有可访问组件：打开时焦点进入、Tab 不逃逸、Escape 关闭非提交中对话框、关闭后恢复焦点。字段错误紧邻输入且有文字说明；提交中禁用重复提交但不清空输入。归档保持历史可查，并提供恢复入口。

## 7. API 所需资源与动作

以下是前端需求契约，路径在 `/api/workbench` 下与后端最终实现对齐；并不声称这些接口已存在。JSON 为权威资源表示，稳定 ID 不由名称生成。时间为带时区 ISO 8601；分页列表返回 `items` 和 `next_cursor`，事件使用单调序号。对无测量值使用 null 并明确原因。

| 资源 | 必需字段 | 必需操作 |
| --- | --- | --- |
| roles | id, name, description, source_path, default_skills | 列表、详情；提供默认角色来源 |
| agents | id, name, role_id, instructions, enabled, model_config_id, skill_ids, tool_scopes, created_at, updated_at, revision | 列表、新建、编辑、停用/启用；行为状态另含 active_run_count 与 reason |
| projects | id, name, authorized_workspace, member_ids | 列表、新建；只返回已授权路径显示值 |
| conversations | id, type, title, project_id, member_ids, archived, updated_at, last_message_summary | 列表、获取/创建私聊、新建群、邀请/移除、归档/恢复 |
| messages | id, conversation_id, sender_type, sender_id, content, created_at, task_id, attachment_ids | 分页读取、幂等发送；消息顺序独立于本地发送时间 |
| tasks | id, conversation_id, project_id, title, objective, scope, acceptance, owner_agent_id, member_ids, status, requirement_version, dependency_ids, budget, created_at | 草案、修改、确认执行、详情、子任务/评审汇总 |
| runs | id, task_id, agent_id, attempt, requirement_version, status, status_reason, started_at, ended_at, worker_id, checkpoint_id, can_resume, usage, cost, error | 列表/详情、停止请求、终止确认状态、指定检查点恢复 |
| events | id, sequence, type, task_id, run_id, agent_id, requirement_version, summary, created_at | 按 cursor 增量读取/订阅、断线续读；不返回秘密和未授权工具原文 |
| artifacts | id, task_id, run_id, name, media_type, size, status, download_url, created_at | 列表、权限校验预览/下载 |
| memories | id, agent_id, project_id, scope, content, source_refs, version, status, created_at | 授权查询、候选详情、批准/拒绝、回滚指定版本 |
| configuration | model/cli entries with id, provider, enabled, configured, masked_fields; max_concurrency, budget_limits | 读取脱敏配置、保存、检查；检查结果含 status, checked_at, error |
| agent perspective | agent_id, visible_context_summary, current_goal, tasks, runs, blockers, granted_scopes | Owner 只读聚合；观察不改变 Agent 的读取权限 |

推荐具体路径模式：`GET/POST /agents`、`PATCH /agents/{id}`、`GET/POST /conversations`、`PATCH /conversations/{id}`、`GET/POST /conversations/{id}/messages`、`POST/DELETE /conversations/{id}/members/{agent_id}`、`GET/POST /tasks`、`PATCH /tasks/{id}`、`POST /tasks/{id}/execute`、`POST /runs/{id}/stop`、`POST /runs/{id}/resume`、`GET /events?after=...`、`GET /agents/{id}/perspective`。最终 API 文档必须记录实现采用的路径及响应，不机械增加平行接口。

写操作携带 `request_id` 幂等键；任务修改携带 expected requirement_version，身份修改携带 expected revision。错误统一包含 code、message、field_errors、retryable、request_id。冲突保留用户草稿并提示重新载入，不盲目自动覆盖。服务鉴权、同源约束及对象权限不可由前端隐藏按钮替代。

初版可用定时增量事件读取实现实时体验，无需同时维护 WebSocket 与 SSE。刷新频率由实际运行状态调整，失败退避；对话列表、身份状态与 Run 均以同一权威状态回读。若后端已有 SSE，则复用。前端不直接访问 SQLite、CLI、Docker、Node 文件系统或 Tauri API。

## 8. 空态、加载、错误、断网

| 状态 | 展示与可执行动作 |
| --- | --- |
| 初次加载 | 骨架只用于空间占位，aria-busy；不出现假消息、假费用或在线状态 |
| 没有会话/没有搜索结果 | 清楚说明，分别提供创建会话/清空筛选 |
| 没有任务/活动/记忆/产物 | 简洁文字说明；只有已有操作才提供按钮，不引导伪造测试数据 |
| 单资源读取失败 | 对应区域错误与重试，其余可用区保持；服务器错误不清空草稿 |
| 模型/CLI 未配置 | 消息/任务说明具体缺少项，提供设置入口；不模拟回复或自动降级为假成功 |
| Docker 不可用 | 身份与历史仍可浏览；需要隔离运行的任务明确阻塞及检查入口 |
| 网络断开 | 页面横幅“连接中断，正在重新连接”；保留最后读取时间、草稿和已有数据；状态标记可能过期 |
| 重连成功 | 从事件 cursor 补取去重，再刷新关键资源；不重复发送用户请求 |
| 冲突/超限 | 显示实际原因，保留输入；提供重新读取或调整限制，不无限自动重试 |

发送规则：Enter 发送，Shift+Enter 换行；中文 IME composition 期间 Enter 不发送。所有按钮键盘可达，焦点明显，状态不只依赖颜色；动态失败通知使用适当 aria-live，历史批量加载不连续播报。输入框高度上限后内部滚动，手机软键盘不能遮住发送按钮。

## 9. 设计和功能验收交接

设计实现前将本稿与 PM/后端契约核对；当前结论为“可进入契约对齐”，不是运行验收 Pass。主屏概念未画出的对话框与空/错状态沿用本设计系统，若实现细节存在视觉歧义先补相应状态概念。

浏览器验收同时保留功能证据和视觉证据：1536 × 1024 原生参考尺寸、实际工作窗口、390 px 窄屏；无法原生尺寸时记录原因。使用 Browser/IAB 优先，只有不可用时说明 Playwright 回退原因。必须在同一 QA 轮使用 view_image 查看概念和最新渲染截图，对比至少布局宽度、白/冷灰/绿配色、字号行高、任务卡与输入框、导航/图标、响应式六项；记录具体差异和修正，不能只靠构建成功。

首屏文案差异表明确列出：动态真实数据替换示例；角色首字替代人物头像；可用/执行中等真实状态替代示意在线；仅有后端能力时展示附件动作；窄屏抽屉为必要适配。除此以外的可见增删须说明具体功能依据。

功能回归覆盖：新建身份后刷新保留；改名后历史不丢；停用后无法新派工；私聊发送失败保留草稿；组群与成员管理；任务确认/版本冲突；停止中到真实终止；检查点恢复；隔离记忆展示；配置失败反馈；重连幂等；键盘与输入法；实际成果打开。每个可独立验收的功能按目标要求分别测试、审查、提交、推送、回读。

Ponytail 决策：复用 Python 服务与一套 API，前端采用小型组件和原生表单；不做通用适配器、复杂状态库、假在线模拟和空壳桌面插件。Tauri 后续复用静态构建及协议，桌面宿主与生命周期在迁移文档中单独落实。
