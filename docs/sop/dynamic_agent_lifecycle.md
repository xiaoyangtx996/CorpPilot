# 动态 Agent 生命周期管理 SOP

## 适用范围

通过 HR 动态创建和回收 Agent 实例的完整流程。

## 角色分工

| 角色 | 职责 |
|------|------|
| 部门负责人 | 提出资源需求 |
| PMO 主管 | 评估合理性、转发 HR |
| HRBP | 分析能力需求 |
| HR 总监 | 审批创建/回收 |
| 招聘专员 | 执行创建/回收 |
| 培训专员 | 验证新 Agent 能力 |

## 创建流程

### 1. 需求提出

- 部门负责人评估项目复杂度
- 确定需要的角色类型和数量
- 向 PMO 提交 resource_request

### 2. PMO 评估

- 确认资源需求合理性
- 检查预算充足性
- 转发给 HR

### 3. 需求分析（HRBP）

- 确认现有 Agent 无法满足
- 明确角色模板和配置要求

### 4. 审批（HR 总监）

- 审批创建申请

### 5. 创建执行（招聘专员）

- 读取 `agents/{dept}/roles/{role}.md` 模板
- 创建 Agent 实例
- 分配唯一 ID（格式：`{dept}_{role}_{序号}`）
- 配置权限和协作关系
- 绑定项目 ID
- 更新 `data/department_roster.json`

### 6. 能力验证（培训专员）

- 验证新 Agent 是否正常工作
- 确认无误后通知部门负责人

## 回收流程

### 1. 回收申请

- 项目完成后，部门负责人提交 recycle_request

### 2. 状态检查（招聘专员）

- 确认目标 Agent 无进行中任务
- 有任务则等待完成

### 3. 执行回收（招聘专员）

- 归档 Agent 执行记录
- 从 `data/department_roster.json` 移除
- 释放资源

### 4. 通知（招聘专员）

- 通知部门负责人、PMO
- 更新资源状态

## 名册更新规则

- 创建时：在对应部门的 `dynamic_agents` 数组中追加
- 回收时：从 `dynamic_agents` 数组中移除
- `default_roles` 永不被修改或回收
