权威范围：2026-09-06 用户下发的完整 Goalcraft 目标。完整浏览器应用与 Tauri 迁移规划；阶段原型不算整体完成。
交付分支 `codex/corppilot-agent-workbench`，每功能测试、审查、提交、立即推送及远端回读。已授权功能分支推送，不含 main、强推、PR、合并、发布及生产部署。

## 产品与技术评审

- PM 范围审查 Pass：会话驱动的个人团队工作台，继承角色/流程治理，普通任务不走全部管理层。
- Tech Lead/Ponytail 方向 Pass：单机 Python 控制服务、标准库 SQLite、有限 Docker Worker 池、静态 React/Vite 前端；不加入 Kubernetes、微服务或预制插件框架。
- UI 设计交接：[设计规格](workbench-design.md)。当前只是设计通过；运行界面和真实链路尚未验收。
- 长期身份、角色模板、会话、任务、Run、项目分开建模。工具镜像可复用，Worker 按任务回收，身份及批准记忆长期保留。
- 已盘点目录：13 个部门 SOUL、34 个专业岗位文件，共 47 个模板；最终还须核对实际配置引用，禁止照搬 README 岗位数。

## 阶段顺序与责任

可靠性 → 身份/持久状态 → 聊天/任务 → 双 Worker/恢复 → 组队/记忆 → 完整浏览器联调回归 → Tauri 文档/最终验收。
每阶段给出 Pass/Return/Escalate；PM 跟进全过程，前后端专业分工，QA 独立验证，主代理集成验收，DevOps 负责环境和恢复，文档随真实状态更新。

先完成已授权且无环境依赖的工作；关键真实链路未测不得判定目标完成。Mock只证明注入场景，不替代浏览器、Docker或真实模型。Docker/WSL系统变更若需要管理员或重启则单独请求最小授权；模型仅用现有授权配置和费用边界。

## 数据与交付边界

- SQLite 默认独立用户数据目录，支持 `CORPPILOT_WORKBENCH_HOME`；测试仅使用临时数据库。
- 旧 JSON 迁移前备份并校验数量/引用，切换后不长期双写；不得删除真实历史/记忆来通过测试。
- Worker 只能得到本次授权上下文、工具和挂载；Owner管理接口不能直接暴露给 Worker。
- 本轮不要求 Tauri 安装包、第二种 CLI、多机集群或自动训练模型；本轮必须真实完成至少一种 CLI 与双 Docker Worker。
- 分功能证据见 [交付台账](feature-delivery-log.md)，不将本地通过标为远端交付。
